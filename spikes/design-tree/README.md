# Design tree (spike)

The repository's design documents as one ThoughtTree tree, kept as an event log and shown by a small viewer.
It came out of the tutor session of 2026-11-27 on event-sourcing patterns and versioning: a way to try the
planned event shapes on real content and to browse the ADRs, the arc42 sections, the UX concept, the open
decisions and the work queue as an outline.

This is a disposable spike: it lives outside `src/`, is not in `ThoughtTree.slnx`, and is not part of the gate,
the banned API lists or the CI builds (AGENTS.md section 5). Nothing in `src/` or `tests/` depends on it.

## Files

- `generator/build.py`: Python 3, standard library only. Reads `docs/adr/`, `docs/adr/bets.md`,
  `docs/architecture.md`, `docs/ux-concept.md` and `docs/plan/next-work.md` and writes an event log, one event
  per line. Ids come from fixed UUIDv5 names and the clock from a fixed start, so the output is deterministic.
- `events.json`: the event log, 1,258 events.
- `index.html`: the viewer. It loads `events.json` from its own folder, replays it in the page and shows the
  tree as an outline beside the selected thought (plaintext, one device, no envelope or encryption).

## Running the generator

From the repository root:

```sh
python3 -I spikes/design-tree/generator/build.py . /path/to/events.json
```

It prints the number of events, the count per type and the file size. It fails with a `KeyError` or an
assertion when the documents hold an ADR that its topic list (`ADR_TOPICS`) does not place.

To view a log, serve this folder over HTTP (the viewer fetches `events.json`, which browsers block from
`file://`), for example `python3 -m http.server` in `spikes/design-tree/`, and open `index.html`.

## The log is not reproducible by build.py

- Events 1 to 1,114 were generated by an earlier revision of `build.py` from the documents at commit `22982a2`.
- Events 1,115 to 1,258 are edits made by hand at the owner's direction (moving, retagging and splitting
  thoughts, new decided items, relations). They exist only in `events.json`; `build.py` does not produce them.

Keep `events.json` byte for byte; do not regenerate it over the hand edits. Running the `build.py` here on
commit `22982a2` gives 1,148 events that do not match events 1 to 1,114: it already splits the UX open questions
into child items, and in the stored log 20 `item.created` events name a parent that the hand edits created later.
